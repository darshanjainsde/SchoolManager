What was found

Every rule here is an incident, not an opinion

Each one is in the file because a screen shipped with it. The number is how many pages carry it today.

Two rules were narrowed after their first run. Matching a word anywhere on a line flagged one student’s three invoices as “roster-scale work”, and a list of thirty classes, because those lines happened to contain invoice and students. The receiver now has to be a bare identifier naming a roll of people. The image rule stopped flagging a missing loading attribute too — an above-the-fold image should not be lazy, so that is a judgement, not a fault.

A rule that cries wolf makes the whole audit ignorable, which is worse than not having the rule. That is why the moderate list is worth reading.

How to run it again

cd apps/web && npx next build > ../../scripts/audit/build.log, then node scripts/audit/page-audit.mjs, then node scripts/audit/scorecard.mjs — which rebuilds this page from log/latest.json. The page has no figures of its own, so it cannot drift from the run.

Each run diffs against the one before, so a page that was perfect last week and is not today shows up as a regression rather than as somebody’s new opinion. That is the whole reason it is a script and not a conversation.

Without build.log the run prints SKIPPED for the bundle rule rather than quietly grading on six rules instead of seven.
